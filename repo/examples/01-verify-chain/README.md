# 示例 1 · 自己算一遍链

**它回答的问题**：我拿到的这份账目，和页面上公示的那份，是不是同一份？

**零依赖**：Python 3.8+，标准库。不用 pip install，不用账号，不用密钥。

```bash
python3 verify.py
```

```
条目数     4
data_notice 测试期数据：W4 结构验证样例（4 条，假 ID）。beta 期替换为真实账目。

  ✅ 链完整　链尾 c8498a30cb61ea4e…
  ✅ 锚值一致　锚值 cdec34e5bb85018a…（页面印的与字节算的一致）
```

## 它算了什么

三件事，都在你的机器上：

| # | 检查 | 判据 |
|---|---|---|
| 1 | 每条记录的哈希 | `hash == sha256(prev_hash + "\n" + canonical(entry))` |
| 2 | 链是否连续 | 第 n 条的 `prev_hash` 等于第 n−1 条的 `hash` |
| 3 | 锚值是否对得上 | `/api/ledger/export` 的字节 sha256 等于 `/ledger` 页面上印的那串 |

`canonical()` 只有一行：`json.dumps(obj, ensure_ascii=False, sort_keys=True, separators=(",", ":"))`。
键排序、无多余空白、UTF-8 不转义非 ASCII。**没有别的规则，也没有隐藏的盐。**

## 想看它真的会报警吗

```bash
python3 verify.py --tamper
```

```
  ❌ 链完整　hash 对不上（重算 b8b333f7d0769d08… / 记录里 59ca03c4d5fec958…）
结论：第 1 条（自 0 起）对不上。
```

它改掉第 2 条的 `unit` 一个字符，第 2 条自己的哈希立刻不匹配。若连哈希一起重算，
第 3 条的 `prev_hash` 就会指错——**改单条还不够，得把后面全改了，而最后一条改完，
锚值就对不上页面**。这就是链的意义：不是让人改不了，是让改动留痕。

## 用在 CI 里

```bash
python3 verify.py --quiet    # chain_ok=True anchor_ok=True items=4
```

退出码 `0` 通过、`1` 不通过、`2` 取不到数。三者可分，不必解析文字。

## 三个边界，说在前面

**一、它证明的是「一致」，不是「为真」。**
三项全过只说明：你拿到的字节与页面公示的一致，且链没断。它不证明记录的内容发生过——
账本记的是**申报与确认**，不是事实本身。有人申报了一件没发生的事，哈希链照样是完整的。

**二、跨语言重算有坑，且坑在数字上。**
Python 的 `json.dumps(2.0)` 是 `"2.0"`，JS 的 `JSON.stringify(2.0)` 是 `"2"`。
同一份数据，两种语言算出两个哈希。本脚本用 Python（与服务器同源）所以不踩；
你要用别的语言重写，必须自己保证浮点数序列化逐字节一致，否则会得到假的"校验失败"。
这也是示例 2 只做统计、不做重算的原因。

**三、取不到数就是取不到数，不要当成通过。**
脚本对网络错误返回 `2`，不返回 `0`。监控里把"取不到"当"没事"，是最常见的一种假装。
