# 示例 1 · 自己算一遍链

**它回答的问题**：我拿到的这份账目，和页面上公示的那份，是不是同一份？

> **先说清楚它不回答什么**：这里要拿来相比的两个数——你算出的导出件字节、页面印的锚值——
> **都出自 `drawcommons.org` 这一台服务器**。所以它证明的是「站内自洽」，不是「这个站没有
> 整份造假」。要跨过那一步，得拿一个不由那台服务器给出的值来比：`REPRODUCE.md` §5 那段
> 锚值基线，随签名 tag 一起发布，**那才是本项目唯一的独立信任根，本脚本不是**。
> 展开见下面第四节「它拿到的两样东西出自同一台服务器」。

**零依赖**：Python 3.8+，标准库。不用 pip install，不用账号，不用密钥。

这里有两个脚本，各管一件事：

| 文件 | 算什么 | 依赖 |
|---|---|---|
| `verify.py` | 链没断、锚值一致——**字节**对不对 | 只有标准库 |
| `verify-confirm.py` | 每条受方确认是谁签的——**人**认没认 | 标准库 + `ssh-keygen` |

```bash
python3 verify.py
```

```
条目数     4
data_notice 测试期数据：W4 结构验证样例（4 条，假 ID）。beta 期替换为真实账目。

  ✅ 链完整　链尾 c8498a30cb61ea4e…
  ✅ 锚值一致　锚值 cdec34e5bb85018a…（页面印的与字节算的一致）
```

（以上是 2026-11-14 的实跑输出，留个样子。条目数会随入账增加、锚值随之改变——所以你
看到别的值是对的；`❌` 才是问题，它的含义见下面那张表。）

## 它算了什么

三件事，都在你的机器上：

| # | 检查 | 判据 |
|---|---|---|
| 1 | 每条记录的哈希 | `hash == sha256(prev_hash + "\n" + canonical(entry))` |
| 2 | 链是否连续 | 第 n 条的 `prev_hash` 等于第 n−1 条的 `hash` |
| 3 | 锚值是否对得上 | `/api/ledger/export` 的字节 sha256 等于 `/llms.txt` 里公示的锚值（`/ledger` 页只有前 8 位入口） |

`canonical()` 只有一行：`json.dumps(obj, ensure_ascii=False, sort_keys=True, separators=(",", ":"))`。
键排序、无多余空白、UTF-8 不转义非 ASCII。**没有别的规则，也没有隐藏的盐。**

## 想看它真的会报警吗

```bash
python3 verify.py --tamper
```

```
  ❌ 链完整　hash 对不上（重算 b8b333f7d0769d08… / 记录里 59ca03c4d5fec958…）
结论：第 1 条（自 0 起）对不上。
```

它改掉第 2 条的 `unit` 一个字符，第 2 条自己的哈希立刻不匹配。若连哈希一起重算，
第 3 条的 `prev_hash` 就会指错——**改单条还不够，得把后面全改了，而最后一条改完，
锚值就对不上页面**。这就是链的意义：不是让人改不了，是让改动留痕。

## 用在 CI 里

```bash
python3 verify.py --quiet            # chain_ok=True anchor_ok=True items=4 confirmations=0
python3 verify.py --tamper --quiet   # chain_ok=False anchor_ok=skipped items=4 first_bad=1
```

退出码 `0` 通过、`1` 不通过、`2` 取不到数。三者可分，不必解析文字。

演示模式下锚值报 `skipped` 而不是 `True`：改的是你手里那份条目，与线上锚值不可比。
替一个**没做的**检查签 `True`，比不签更坏——CI 里也一样。

# 第二件事 · 确认是谁签的（`verify-confirm.py`）

`verify.py` 只回答「链没断、锚值一致」。还有一类话是**人说出来的**，不是算出来的：

> 这条 `give`，收下东西的那个人认了。

导出件里每一条 `confirmations` 就是这么一句话，带一个签名和一把公钥。它进锚值，所以
被改过你能发现；但「它到底是不是那个人签的」，哈希算不出来——要看签名。

```bash
python3 verify-confirm.py           # 验线上
python3 verify-confirm.py --export export.json   # 验手里那份（可离线）
```

```
条目数        6
受方确认      1 条

  ✅ 已确认　g-rq_abc12345　←　pt_alice　SHA256:3P40AfNRw6l4…

结论：每一条确认都由它自称的那个主体签的，且签的是这条内容算出来的 hash。
      这不证明条目描述的事发生过——它证明的是「这个主体认过这条记录」。
```

它按顺序做五件事，缺一件就不算「已确认」：

| # | 做什么 | 少了会怎样 |
|---|---|---|
| 1 | 自己把链接一遍，算出这条的 hash | 只信导出件自述的 hash，「把条目换掉、hash 照抄」能过去 |
| 2 | 拼 `drawcommons-confirm-v1\n<entry_id>\n<hash>\n` | 换取「签什么」的规则，等于信我们说的 |
| 3 | 算公钥指纹，比对 `key_fp` | 换钥这种事查不出来 |
| 4 | `ssh-keygen -Y verify -n drawcommons-confirm` | 没验，就是「我们说是他签的」 |
| 5 | 五步全过才写「已确认」 | 「没法验」被写成「通过」，是这里最坏的一种 |

**它为什么单独一个文件，不并进 `verify.py`。** 第 4 步要调 `ssh-keygen`，而 `verify.py`
的承诺是「只要标准库、不用装任何东西」。为了凑成一个脚本而偷偷加一个依赖，那句承诺
就变成半句真话。两件事、两个文件、两句话，各自都说实话。

**「无法验」不是「通过」。** 确认里没带 `pubkey`、或者你机器上没有 `ssh-keygen`，
脚本会明确写「无法验」并以退出码 `1` 结束——它不会替你猜。什么时候会缺 `pubkey`？
不该缺：导出件里的每条确认都带。缺了说明有东西不对，那正是该停下来问的时候。

## 四个边界，说在前面

**一、它证明的是「一致」，不是「为真」。**
三项全过只说明：你拿到的字节与页面公示的一致，且链没断。它不证明记录的内容发生过——
账本记的是**申报与确认**，不是事实本身。有人申报了一件没发生的事，哈希链照样是完整的。

**二、跨语言重算有坑，且坑在数字上。**
Python 的 `json.dumps(2.0)` 是 `"2.0"`，JS 的 `JSON.stringify(2.0)` 是 `"2"`。
同一份数据，两种语言算出两个哈希。本脚本用 Python（与服务器同源）所以不踩；
你要用别的语言重写，必须自己保证浮点数序列化逐字节一致，否则会得到假的"校验失败"。
这也是示例 2 只做统计、不做重算的原因。

**三、取不到数就是取不到数，不要当成通过。**
脚本对网络错误返回 `2`，不返回 `0`。监控里把"取不到"当"没事"，是最常见的一种假装。

**四、它拿到的两样东西出自同一台服务器。**
第 3 项检查比的：「你算的导出件字节」与「`/llms.txt` 公示的锚值」——两个都来自 `drawcommons.org`。
所以它证明的是**这个站内部自洽**，不是「这个站没有整份一起造假」：一台存心骗人的服务器
完全可以给你一份改过的导出件、再按那份字节现算出锚值公示出来，两项照样相等。

要跨过这一步，只有一个办法：**拿一个不由那台服务器给出的值来比**。本仓库提供的是
`REPRODUCE.md` §5 那段基线——它写在仓库里，跟签名 tag 一起发布，改它就会破坏 tag 的签名。

但要看清它的局限：基线只对应**某一个时刻**。账本每进一条，锚值就变，所以你算的值与基线
不同，通常只说明账本长了几条，不说明被改过。**基线管的是「历史没被重写」，本脚本管的是
「现在这份没被改」**——两件事，缺一件都只剩半句保证。

**把这件事说成一个词：本脚本不是信任根。**
它做的是「两个数相等」的比较，而这两个数出自同一个签发者；同源的两个数相等，只能说明
签发者前后一致，不能说明签发者没撒谎。本项目里**唯一的独立信任根**是 `REPRODUCE.md` §5
那段锚值基线——它写在仓库里、随签名 tag 发布、不在服务器上，改它就会破坏 tag 的签名。

| 谁给出的值 | 能证明 | 不能证明 |
| --- | --- | --- |
| 本脚本（页面 + 导出件，同一台服务器） | 这份字节没被改过、链没断 | 服务器有没有整份造假 |
| `REPRODUCE.md` §5 基线（仓库 + 签名 tag） | 历史上某个时刻的锚值没被重写 | 现在这份对不对（账本会长） |

两句合起来才是完整的一句话。只念其中一句是**半句保证**——而半句保证比没有保证更危险，
因为它听起来像已经验完了。
