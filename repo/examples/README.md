# 十分钟接入

> **本版本未生效。** 协议 v2.1-r5 处于公示期（起算 2026-11-12，计划生效日 2026-12-21），
> 尚未生效。当前站点是 beta，账本里是 4 条结构验证样例（假 ID）。接入可以做，但别把
> 它当成已生效的服务承诺。

三个只读接口，没有账号、没有密钥、没有 SDK。你能做的第一件事不是"申请接入"，
而是**自己验一遍**——所以我们把这件本不该由你做的事，写成了十分钟。

---

## 0–1 分钟 · 它有什么

| 接口 | 返回 | 用途 |
|---|---|---|
| `GET /api/ledger/items` | 全部条目，每条带 `prev_hash` / `hash` | 拿走数据 |
| `GET /api/ledger/verify` | `{ok, first_bad, chain_tail, genesis}` | 看服务端自检结果 |
| `GET /api/ledger/export` | 导出件原文，**它的 sha256 就是锚值** | 校验的基准 |

```bash
curl -s https://drawcommons.org/api/ledger/export | sha256sum
# cdec34e5bb85018a9a0d905307ee2103fa1ee7a9f046290987cc1a801efe30a9
```

拿这个值去对 `https://drawcommons.org/ledger` 页面上印的锚值。**对上了，说明你拿到的
字节就是它公示的字节**。这一步不需要读我们的任何代码。

## 1–4 分钟 · 验一遍（示例 1，Python，零依赖）

```bash
cd 01-verify-chain && python3 verify.py
```

```
条目数     4
  ✅ 链完整　链尾 c8498a30cb61ea4e…
  ✅ 锚值一致　锚值 cdec34e5bb85018a…（页面印的与字节算的一致）
```

它做三件事，全在你机器上：重算每条记录的哈希、检查 `prev_hash` 是否真接上一条、
比对导出件字节与页面锚值。想看它会不会报警：`python3 verify.py --tamper`。

**这一步的意义**：从这一分钟起，"账本没被改过"不再是我们的说法，而是一个你能复算的事实。

## 4–7 分钟 · 用起来（示例 2，Node 18+，零依赖）

```bash
cd 02-consume-json && node summarize.mjs   # 写出 out.html
```

产出是一段自包含的 HTML 卡片：条数、链尾、按状态/类别/可核验程度的分布，底部署名行。
样式内联、类名带 `dc-` 前缀，直接嵌进你已有的页面不会打架。

数据是 **CC-BY-4.0**：商用、改作、再分发都不需要另行许可，唯一条件是保留署名。
生成器已经把署名写进产物末尾——删掉它，你的使用就不再合规。

两个坑写在示例 README 里，这里只提一句：**不要把不同单位的 `quantity` 相加**，
**`verifiability` 不是可信度评分**。

## 7–9 分钟 · 盯住它（示例 3，sh，零依赖）

```bash
cd 03-monitor-shell && ./check.sh
```

```
2026-11-12T15:12:38Z  OK  count=4  anchor=cdec34e5bb85018a…  (新)
```

一行一条，落进 `state.tsv`。退出码 `0` 正常、`1` 链坏或锚值回退、`2` 取不到数。
挂 cron 就是每天一行记录——**巡检要留下痕迹，不能只有一句"我看过了"**。

---

## 9–10 分钟 · 接进 AI 客户端（示例 4，MCP，零依赖）

```bash
cd 04-mcp-server && python3 selftest.py       # 先自检，再往客户端里装
```

三个接口被包成三个 MCP tool：`ledger_items` / `ledger_verify` / `ledger_export`。
装到 Claude Code 里是一条命令，Claude Desktop 与 Cursor 是一段 JSON，写法在
[`04-mcp-server/README.md`](04-mcp-server/README.md)。

它跟"把接口包一层"的区别只有一处，但那一处是关键：`ledger_verify` **不采信服务端的
`ok`**，它自己拉数据、在本机重算哈希链与锚值，再把两边摆在一起。服务端说通、本机算出
断链时，它报断链。

## 然后呢

你现在能做但还没做的三件事，按价值排序：

1. **把它接进你自己的系统**。数据 CC-BY，代码 Apache-2.0，两边都不拦商用。
2. **发现不对劲就说**。锚值对不上、接口返回怪东西、文档和实现对不上——都可以开 issue。
   我们更愿意被指出问题，而不是被夸。
3. **别急着依赖它**。它还是 beta，字段与口径都可能变，账本里是假 ID 的样例。
   现在适合"试"，不适合"押"。

## 三条边界，先说清楚

**一、验哈希用 Python，别用 JS 重写。**
Python 的 `json.dumps(2.0)` 是 `"2.0"`，JS 的 `JSON.stringify(2.0)` 是 `"2"`。
同一份数据算出两个哈希，你会得到一个假的"校验失败"，然后开始怀疑数据——而数据是对的。

**二、账本记的是申报与确认，不是事实本身。**
链完整只能证明"这份记录与入链时一致"，不能证明"这件事真的发生过"。
有人申报了一件没发生的事，哈希链照样完整。所以别把"链校验通过"读成"内容可信"。

**三、现在是 beta，口径会变。**
4 条样例是结构验证用的假 ID。字段增删会随版本走，`rule_version` 就是干这个的。
真要把数据用于决策，等到 30 日公示期满、协议生效之后。
