# 示例 3 · 每天跑一次，记两件事

**它回答的问题**：站点还活着吗？账本有没有被悄悄换过？

**零依赖**：POSIX `sh` + `curl` + `sha256sum`。不需要 jq（接口是固定 `indent=2` 输出）。

```bash
./check.sh
```

```
2026-11-12T15:12:38Z  OK  count=4  anchor=cdec34e5bb85018a…  (新)
2026-11-12T15:12:43Z  OK  count=4  anchor=cdec34e5bb85018a…  (未变化)
```

一行一条，落地到 `state.tsv`（制表符分隔：锚值、条目数、时点）。**这个文件本身就是巡检记录**——
30 天公示期里，"每天都看过"这件事得留下痕迹，不能只有一句"我看过了"。

## 三种退出码，对应三件事

| 码 | 含义 | 你该做什么 |
|---|---|---|
| `0` | 正常。（含"有新条目"——追加是正常的） | 不用 |
| `1` | 链坏了，或锚值回退 | 立刻查 |
| `2` | 取不到数 | 看是网络还是站点；**别当成功** |

`0` 与 `2` 分开是关键。监控里把超时当通过，是最常见的一种假装：
「昨晚告警了吗」「没有」「那没事」——其实那晚根本没连上。

## 为什么第四种情况要单独判

只比"锚值变没变"会漏掉一种：**链被换回一个旧状态**。锚值变了，但变回了一个曾经出现过的值。

账本承诺只追加，所以锚值序列的合法形态只有一种：一直出现新的。因此判据是——

```
当前锚值在历史里出现过，却不是最后一行  →  ANCHOR_ROLLBACK
```

```
2026-11-12T15:12:51Z  ANCHOR_ROLLBACK  anchor=cdec34e5…  count=4  上一次=ffffffff…
```

这时候 `count` 可能变小、也可能不变，两种都不影响判定——**判定看的是锚值在序列里的位置，不是数值大小**。

## 挂到 cron

```cron
# 每天 03:17 UTC，日志按月切
17 3 * * *  STATE=/var/lib/dc/state.tsv /opt/dc/examples/03-monitor-shell/check.sh >> /var/log/dc-check-$(date +\%Y\%m).log 2>&1
```

`STATE` 要放在**持久卷**上。放 `/tmp` 里，机器一重启历史就没了，"回退"也就永远判不出来。

## 两个边界

**一、这份状态是本机的。** 换一台机器跑，历史从零开始，第一次只会记一条"新"。
真要连续观测，就固定一台机器、一个状态文件；或者把 `state.tsv` 提交到你自己的仓库里
（它只有三列，不含任何个人信息）。

**二、`ANCHOR_ROLLBACK` 不等于有人作恶。** 它只说"当前锚值在这台机器的观测历史里出现过、
但不在末尾"。合法成因也存在（比如你把旧的状态文件拷了回来）。它的价值在于：
**每一次出现都值得看一眼**，而不是自动判定为事故。
