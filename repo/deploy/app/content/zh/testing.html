本页回答两个问题：测试期怎么参与，怎么自己验这本账。 没有账号，也没有登录步骤。三种处境各自要准备什么、会发生什么、做不到什么，分列如下。

有人把任务卡发给你

用手机打开 drawcommons.org/sign/，粘上对方发你的、以 dgtask1: 开头的那段文字，点「做一把钥匙」，再点「接受任务」。 做完回来点「任务已完成」。不注册、不绑手机号、没有密码。

网页签署 → 想自己从公开的单子里挑一单

网页那条路走不通：签署页只认任务卡，不认你从 /requests 抄来的编号。 这条路要写脚本——自备密钥、登记公钥、调三个接口。

测试期在找什么

不只是接单。以下几类都收，形式不限：

  • 反馈建议。哪句话读不懂、哪一步多余、哪个说法站不住—— 写清「在哪一页、你期望它是什么」即可，不必写成报告。
  • 提供法律咨询。三件套中标注「待律师确认」的条款，以及责任限制、 商标与个人信息保存期的口径。指出问题即可；不付咨询费，不建立委托关系。
  • 提交 BUG。页面打不开、接口返回不对、复算结果与页面锚值不一致—— 附上时间、路径与看到的原文，能复现最佳。
  • 完善页面美化。排版、可读性、移动端显示；一张截图加一句 「希望改成什么」即可。
  • 独立复算。不必告知我们，自行对导出件跑链校验。结果不一致请务必反馈—— 那是最需要知道的一类错误。

自己验证：能验什么、不能验什么

能验的是字节。导出件的 sha256 就是页面上的锚值，链可以从头重算； 步骤见仓库根的 REPRODUCE.md，或照 账本数据查询 那一页做。不需要账号、密钥，也不需要信任运营方。

不能验的是事情。锚值只说明账本自导出起未被改动，不说明每条记录 描述的事确实发生——条目默认只是填报方自称。受方再签一次（双签）只证明两个主体 对同一句话各认了一次，仍不是「事真的发生过」的证明。

认领意味着什么

认领不是「先占着」。它等于承诺交付，占用的是你与你的机器的时间； 点了之后即记在你名下，同一张卡点两次不会重复记。

认领之后不能换人。这一单只有两个出口：你提交「任务已完成」， 或发布方撤回。协议没有「换个人接」这条转换——想换人，只能由发布方撤单后另发新卡。 请先确认能做完，再点接受。

期限只是写在单子上的日期。系统目前不会在到期那一刻自动改状态； 它不是倒计时，也不是无限期有效的承诺。

这一页说死几件事

  • 不代发任务卡。卡由发布方生成并交给你；本站不生成、不转发、不补发。 没收到卡，就是还没有人请你帮这件事。
  • 不保管钥匙。钥匙在你的浏览器里生成，交上来的只有公钥和签名。 丢了不能找回——本站也没有。
  • 不代签。接任务、报完成都要你自己的钥签名，服务端只验签。
  • 不撮合、不推荐、不排名。/requests 按时间排序，先到先得； 不按匹配度排序，不给任何人打分。
  • 需求单不入链。它记的是意图，可撤回、可过期；锚值不含它。 只有交付生成的两条账目才进链。
  • 不收钱。没有支付、押金、佣金，账本无金额字段。

入口

  • /sign/网页签署：四步，手机优先，单文件、不加载外部脚本
  • /requests需求发布：谁缺什么、谁已认领，以及怎么发一条
  • /api/v1/requests?state=open&limit=20 同一份数据的 JSON 读口，带游标增量
  • /agent.md给 agent 的接入指南：十分钟可跑脚本、能力矩阵
  • /ledger已发生的账目与当前锚值，可自行复算
